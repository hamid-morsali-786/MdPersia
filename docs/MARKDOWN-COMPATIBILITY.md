# دامنهٔ سازگاری نمایش Markdown

ترتیب بررسی: ابتدا حذف یا تغییر ناخواستهٔ محتوا، سپس ساختار سند و ناوبری، سپس چیدمان و در پایان خواندن/ذخیرهٔ فایل‌های ویندوز.

| نمونه | رفتار مورد انتظار |
|---|---|
| مثال Markdown شامل حصار Mermaid | مثال به شکل کد می‌ماند؛ فقط حصار واقعی Mermaid نمودار می‌شود. |
| متن آغازشده با خط افقی | متن عادی میان دو جداکننده باقی می‌ماند. بلوک ابتدایی با کلید متادیتا می‌تواند front matter باشد. |
| عنوان Setext یا عنوان داخل نمونهٔ کد | اولین عنوان سطح یک واقعی برای عنوان سند انتخاب می‌شود. |
| دستور pagebreak در کد | به‌صورت متن دیده می‌شود. |
| فهرست کار و پانویس | وضعیت انجام کار و مرجع/بازگشت پانویس قابل مشاهده هستند. |
| لینک به تیتر فارسی تکراری | شناسهٔ تیتر دوم پسوند عددی می‌گیرد. |
| جدول عریض | در نمایش صفحه، پیمایش افقی به خود جدول محدود می‌شود. |
| فایل UTF-16 یا UTF-32 با BOM | نمایش و ویرایش با حفظ ترتیب بایت و نوع پایان خط انجام می‌شوند. |

آزمون‌های بازگشت در tests/test_markdown_compatibility.py هستند. پردازش ۶۵۲ مثال CommonMark 0.31.2 یک آزمون اجرای پارسر بوده است، نه مقایسهٔ پیکسل‌ها یا اثبات تطابق کامل با مشخصات. نمایش فرمول، BiDi، رنگ‌بندی کد و نمودار همچنان آزمون‌های جداگانه دارند.

دامنهٔ این پشتیبانی اسناد ایستای Markdown است. افزونه‌های وابسته به محیط میزبان مانند transclusion و جست‌وجوی مخزن در Obsidian، کامپوننت‌های JSX در MDX یا اجرای سلول‌های دفترچهٔ محاسباتی به محیط اجرای دیگری وابسته‌اند. پیش‌نمایش HTML می‌تواند با Word و با موتور تبدیل اختیاری قدیمی متفاوت باشد.
